# Lighthouse baseline, 2026-10-01

Mobile Lighthouse run of the **public production** Tokyo Sushi pages and of the **YGF test environment** (`ygf.brunomoyse.be`; the YGF webshop is not in production yet), taken before the Phase 1+ fixes land so later PRs can be compared against it. Read-only page loads, like a normal visitor.

- Tool: Lighthouse 12.8.2, `--form-factor=mobile` (default simulated throttling), headless Chromium 148 on aarch64 (Fedora), categories performance / accessibility / SEO / best-practices.
- Both brands: browser language forced to French (`--lang=fr-FR` plus `Accept-Language: fr-FR`). See the note below on why.
- One run per page (no median of several), so expect roughly +/-5 points of performance noise.
- Raw JSON reports are intentionally not committed.

## https://tokyosushibarliege.be/fr

| Performance | Accessibility | SEO | Best practices | LCP | CLS | TBT | FCP | Speed Index |
|---|---|---|---|---|---|---|---|---|
| 76 | 96 | 100 | 100 | 3.9 s | 0.000 | 260 ms | 3.3 s | 3.3 s |

LCP element: the hero `<img>` (`restaurant-illustrated-mobile.avif`, `fetchpriority=high`). Failing audits: `color-contrast`, `image-redundant-alt` (3 elements each).

## YGF (test environment, https://ygf.brunomoyse.be)

These numbers come from the test environment, not production (`ygfliege.be` is still the static showcase site), so hosting, caching and data differ from what production will serve.

| Page | Performance | Accessibility | SEO | Best practices | LCP | CLS | TBT | FCP | Speed Index |
|---|---|---|---|---|---|---|---|---|---|
| `/fr` | 64 | 96 | 69 | 100 | 7.4 s | 0.000 | 130 ms | 4.4 s | 4.4 s |
| `/fr/menu` | 61 | 96 | 69 | 100 | 8.7 s | 0.001 | 180 ms | 4.8 s | 4.8 s |

- SEO 69 is expected here: the test environment is deliberately non-indexable (`robots.txt` serves `Disallow: /` and responses carry `x-robots-tag: noindex, nofollow`), which fails `is-crawlable`. Expect it to be about 100 on the production domain.
- `/fr` LCP element: the hero bowl `<img>` (`bowl-creative-640.avif`). `/fr/menu` LCP element: a `loading="lazy"` bowl image (`beef-bone-top-800.avif`), which delays LCP. Worth fixing in Phase 1+.
- Failing audits: `color-contrast` (4 elements on `/fr`, 9 on `/fr/menu`).

## Note: browser-language redirect

A first run with Lighthouse's default English browser language did not measure the `/fr` pages: the site sent the visitor to `/en` (client-side for the home page, `/fr/menu` -> `/en/menu`; `i18n_redirected=en` cookie). Those runs scored: home 78 / 96 / 92 / 100 (LCP 4.1 s, TBT 240 ms), menu 62 / 96 / 100 / 100 (LCP 15.0 s, 93% of it render delay, TBT 200 ms). The French figures above are the baseline; the English-browser menu LCP of 15 s is worth keeping in mind when working on menu rendering in Phase 1+. A curl with `Accept-Language: fr-FR` or none returns 200 and sets `i18n_redirected=fr`.

## Not covered

- **YGF production**: not live yet. Re-run against the production URL once deployed (SEO and caching will differ from the test environment).
- **axe / accessibility on cart and checkout, and the cart and checkout pages themselves** need an authenticated session and a populated cart, so they are deferred. Accessibility scores above only cover the public home and menu pages.

## Reproduce

```bash
CHROME_PATH=/path/to/chromium npx --yes lighthouse@12 https://tokyosushibarliege.be/fr/menu \
  --only-categories=performance,accessibility,seo,best-practices --form-factor=mobile \
  --output=json --output-path=./menu.json \
  --extra-headers='{"Accept-Language":"fr-FR,fr;q=0.9"}' \
  --chrome-flags="--headless=new --no-sandbox --lang=fr-FR"
```
